# 删除会话 1.3.0：批量删除

> 适用版本：`dsh-session-delete` 1.3.0（`health.build = 7`）。
> 7 与 6 的主机删除逻辑**完全相同**，7 只是「带批量删除的版本」标记；批量删除本身是浏览器端能力，装好后刷新页面即可用，不需要为它重启。

## 为什么加

1.2.0 解决了「单个会话删不掉」——包括打开过的、正在运行的、以及当前正在看的对话。
但真实使用里会话会持续堆积（开发机当前工作区就有 46 个），想清理旧对话只能一条条点「⋯」→「删除会话」→「删除」，几十次重复点击没有必要。

1.3.0 在同一个菜单里加了 **批量删除会话…**：勾选多个会话，一次删完，逐条回报结果。

## 交互

入口在侧栏会话行的「⋯」菜单里，紧挨着单项「删除会话」，右侧显示当前存储的会话总数（不含空白新会话）：

```
⋯ → 删除会话
    批量删除会话…        46
```

点开后是一个可勾选的列表：

* 数据与侧栏同源：所有已存储会话，按更新时间倒序，**含已归档会话**；「已归档」「运行中」分别有标签；还没聊过的空白会话不列出；
* 每行显示标题、会话 ID 与日期；没有标题的显示「未命名」；
* 顶部搜索框按标题或 ID 过滤；「全选 / 取消全选」只作用于当前筛选结果；
* **当前正在看的对话也在列表里，但置灰、不可勾选**，悬停说明原因（见下文）；
* 勾选后点「删除 N 个会话」：逐条执行，显示「正在删除 3 / 12…」，删掉的行走实时消失；
* 有失败时失败项保持勾选并列出主机返回的原因，按钮变成「重试失败项」，重试只重发失败的那几条；
* 删除过程中 Esc、点遮罩、关闭与取消都不响应，避免删到一半把界面收了。

## 实现

### 座位

| 内容 | slot | id | order |
| --- | --- | --- | --- |
| 批量菜单项 | `sidebar.workspaces.session.menu.item` | `dsh-session-delete.batch` | 510（单项是 500） |
| 批量弹窗 | `shell.overlay` | `dsh-session-delete.batch-dialog` | — |

两个弹窗（单项 / 批量）共用插件内同一个 pending 状态，打开批量时单项弹窗自动让位。

### 列表数据从哪来

用 slot 分配给 overlay 的标准 props `useSessions`、`useWorkspaces` 直接读页面自己的会话存储与归档集合：

* 和侧栏完全同源，不会出现「侧栏有、弹窗没有」；
* 不需要主机新增「列出所有会话」接口；
* 会话被删除后存储更新，列表与勾选状态自动跟着收缩。

### 删除循环

批量没有新的主机路由，浏览器逐条调用单项删除的同一个接口：

```js
POST /dsh-session-delete/delete
{ "sessionId": "...", "force": true }
```

带 `force` 是有意的：批量列表里可能有「打开过、仍被主机加载、还有运行中回合」的会话，单项删除正是靠 `force` 先停工作、再用捕获的生命周期句柄做一次完整收尾，然后才删文件。

逐条而不是并发，原因有三：

1. 每条单独回报成功/失败，失败原因能精确落到某个会话；
2. 删除过程中页面照常重绘，列表一条条变短，用户看得见进度；
3. 不会因为某一条卡住（单条收尾上限 20 秒）就把整批一起拖死，后面的条目继续。

收尾语义：

* `session/not-found` 视为成功（目标已经没了，结果成立）；
* 其他失败进入失败列表，全部跑完后失败的会话保持勾选，点「重试失败项」只重发这些；
* 某条成功但主机回 `notified: false`，说明页面通知没发出去，结束时主动拉一次会话基线；
* 全部成功时弹窗直接关闭，侧栏对应行已消失。

### 为什么当前对话不参与批量

删除当前对话需要页面**先放手**它：单项删除会先执行「新建会话」并等 `retainedBy.mainView` 归零，再请求主机；失败还会切回原对话。
把一个「先切走再删」的状态机塞进批量列表，会让批量在中途改变用户所在的对话、并引入「部分成功后停在哪」的问题。
所以批量把当前对话显示为不可勾选，并提示「先切换到其他对话，再用单项删除」——两条路径各管一件事。

### 没有新增主机路由

批量完全可以在客户端用现有接口拼出来，主机半因此保持 1.2.0 的删除实现不变：

* 少一份要跟着演进的删除流程；
* 已通过 `tests/route.test.mjs` 验证的单项删除路径原样复用；
* 关掉页面时语义清楚——已经发出的删除继续完成，还没发出的保留。

**真机**：

* 运行中的 GUI 里 `sidebar.workspaces.session.menu.item` 出现 `dsh-session-delete.batch`（order 510，active），`shell.overlay` 出现 `dsh-session-delete.batch-dialog`，各一份；

## 已知边界

* 批量逐条执行；单条收尾上限 20 秒，卡住的会话会让整批慢下来但不会阻塞后续条目；
* 中途关掉页面只会让**还没开始**的条目保留下来，已删的不会回滚；
* 不级联删除子代理（subagent）会话日志；
* 删除不可撤销，只想隐藏请用「归档」。
